# 前端设计方案（已全部实施）

> 状态：P1 结构重排、P2 视觉系统、P3 状态与反馈、P4 精修均已完成并构建验证（2026-08-01）。
> 数字滚动动画按方案约定第一版不做；移动端为代码级走查（表格横向滚动、工具栏换行），未做真机截图核对。

## 第二轮设计：「行情台」方向（2026-08-01，已实施）

依据 frontend-design 技能流程（brainstorm → 自我否决默认项 → 构建）：

- **方向**：工具的本质是二手行情监控——商品表的价格统计就是持仓报价，队列就是采集流水线。把价格/进度/计数当作行情数据排版，而不是普通 CRUD 后台。
- **签名元素**：全站 measurement 场景（KPI 数字、价格列、进度计数、ETA、最后爬取时间）统一使用等宽字体 IBM Plex Mono（`@fontsource/ibm-plex-mono`，Tailwind `font-data`）。等宽在这里不是「技术感装饰」，排版对象本身就是度量数据。
- **布局升级**：
  - 运行中队列从表格行升格为「正在执行」控制台面板：呼吸点 + 大进度条 + 大号完成计数 + 分状态明细 + **ETA 预计剩余时间**（剩余条目 × 间隔秒数）+ 操作按钮。
  - 入队表单收进 Collapsible：队列开始执行时自动收起让位，追加条目时强制展开。
- **前端逻辑增强**：商品表中位数/均价/爬取数量/最后爬取/回收价五列支持点击列头排序（空值永远沉底，再点反向）。
- **已否决**：衬线大标题+陶土色（AI 默认脸）、改动品牌琥珀（brief 钉死）、无谓的滚动动画。

## 第三轮：侧边导航（2026-08-01，已实施）

用户反馈单页堆砌过多，引入信息架构层：

- **HashRouter + 左侧固定导航**（移动端 Sheet 抽屉），五页面：概览（KPI + 队列控制台）/ 商品管理 / 标签管理 / 抓取数据 / AI。选 HashRouter 是因为 axum 静态托管无需任何路由回退改动。
- 全局状态与队列轮询保留在 `App.tsx` 顶层，路由页面只是视图——切页不打断轮询。
- 队列运行时导航「概览」项尾部显示琥珀呼吸点，任何页面可感知系统在执行。
- 原方案 A/B 选型（单页优先）随内容增长被推翻，记录于此。

## 1. 现状诊断

当前前端（`web/src/App.tsx` + 5 个 sections 卡片）的问题：

1. **信息层级倒置**：页面上五个卡片简单竖排（Tags → Queues → Products → Ai → Items），按代码编写顺序排列，而不是按使用频率和工作流排列。真正需要盯着的「队列执行状态」被埋在第二位，AI 配置这种低频管理项却占据宝贵的首屏。
2. **无视觉锚点**：整页 `max-w-6xl` 单列灰底白卡，shadcn 默认 zinc 配色，无品牌色、无重点强调，所有信息视觉权重相同——扫一眼抓不住「现在系统在干什么」。
3. **缺概览层**：没有 KPI/状态汇总。用户进入页面第一件事是人工扫五个卡片才能拼出全貌：有几个商品、队列跑到哪了、上次什么时候爬的。
4. **空间利用差**：桌面宽屏下单列布局两侧大片留白；ItemsCard 原始数据表格反而最缺宽度，被挤在同样的列宽里。
5. **反馈与状态薄弱**：loading 无骨架屏、空数据无空态设计、队列运行中只有文字状态，没有进度条/动画等「活着」的感觉。
6. **低频操作未收纳**：AI 供应商管理、AI 工具调用审计是配置/审计性质，与日常操作混在同一层级。

## 2. 设计定位

- **模式（Mode）**：Operate——这是一个个人运营控制台，目标是「快速完成任务」，不是展示。可扫描性、一致性、真实使用场景优先于表现力，品牌只体现在精确的细节上。
- **用户场景**（假设，待确认）：单一用户（你自己），桌面为主，典型动线是：
  1. 打开页面 → 一眼确认系统状态（服务是否正常、队列跑到哪）；
  2. 高频：建队列/追加条目/暂停恢复，看商品统计；
  3. 中频：维护商品和标签；
  4. 低频：配置 AI 供应商、翻原始抓取数据、查工具调用审计。
- **设计一句话**：把「监控台」放在首屏中心，把「配置」收进侧栏，把「数据」给足宽度。

## 3. 信息架构与布局

### 方案选型

| 方案 | 说明 | 结论 |
| --- | --- | --- |
| A. 单页仪表盘网格 | 保持单页无路由，重排为「概览条 + 主次分区」网格 | **推荐**。个人工具，一屏尽览，改动小、风险低 |
| B. 侧边导航 + 多页面 | 引入路由，队列/商品/数据/设置分页 | 否决。当前内容量撑不起多页面，徒增导航点击和路由复杂度 |

### 方案 A 布局结构（桌面 ≥1024px）

```
┌──────────────────────────────────────────────────────────────┐
│ Header：闲鱼管理台 · 服务状态徽章 · 深色模式开关                │
├──────────────────────────────────────────────────────────────┤
│ KPI 概览条：运行中队列 │ 待处理条目 │ 商品总数 │ 今日已爬 │ 最后爬取 │
├───────────────────────────────┬──────────────────────────────┤
│ 主区（2/3 宽）                 │ 侧栏（1/3 宽）                │
│ ① 队列监控（英雄位）            │ ② 标签管理（紧凑列表）         │
│   - 运行中队列：进度条+当前条目  │                              │
│   - 等待/暂停队列：紧凑列表      │                              │
│   - 新建队列 / 追加条目         │                              │
├───────────────────────────────┴──────────────────────────────┤
│ ③ 商品管理（全宽工作表：统计列右对齐 + 勾选入队）                │
├──────────────────────────────────────────────────────────────┤
│ ④ 抓取数据（全宽表格，含刷新/空态/骨架屏）                      │
├──────────────────────────────────────────────────────────────┤
│ ⑤ 低频区（Tabs 收纳）：AI 接口配置 │ 调用记录                   │
└──────────────────────────────────────────────────────────────┘
```

> 实施注（P1 落地时修正）：商品表有 10 列统计字段，塞进 1/3 侧栏会严重溢出，故商品管理下移动为全宽工作表，侧栏只放标签管理。移动端（<768px）退化为单列：概览条 → 队列 → 标签 → 商品 → 数据 → AI。

### 关键决策

1. **队列是英雄位**：运行中队列渲染为「大卡片」——队列名/选择器摘要、进度条（已完成/总数）、当前正在爬的商品名、条目间隔、暂停/取消按钮；等待与暂停队列压缩成列表行。轮询中状态用呼吸动画暗示「活着」。
2. **KPI 概览条取代人工巡检**：5 个小指标卡，数字用 `tabular-nums`，数据来源复用现有 state（queues/products/items），零新增 API。
3. **低频功能 Tabs 收纳**：AI 供应商管理和工具调用审计合并为一个卡片的两个 tab，退出首屏竞争。
4. **标签进侧栏、商品全宽**：标签管理是低频轻量配置，收进 1/3 侧栏；商品表含 10 列统计字段，是高频工作表，给全宽。二者仍上下相邻，配合操作动线。
5. **数据表格全宽**：ItemsCard 移到页面底部占满宽度，后续加分页/筛选也有空间。

## 4. 视觉方向

### 配色

保留 shadcn 体系（不动组件库 token 结构），注入品牌个性：

- **主色（accent）**：暖琥珀黄 `#F5A623` 系——呼应闲鱼品牌的黄色，但降饱和以避免刺眼，仅用于：主按钮、进度条、运行态标识、KPI 数字强调。
- **基底**：浅色模式暖灰底（`--background` 微暖，如 `40 20% 97%`），卡片纯白，细边框投影二选一（不要两者都重）。
- **状态色**：运行=琥珀、等待=蓝灰、暂停=橙、完成=绿、失败/取消=红，全局限定这 5 个语义色，其他地方不滥用彩色。
- **深色模式**：token 已存在（`.dark`），本次接通——header 加切换开关，`ThemeProvider` 落 localStorage。深色下琥珀色提亮至 `#FBBF24` 保持对比度。

### 字体与数字

- 中文 UI 用系统字体栈即可，**重点在数字**：所有统计数字、价格、进度统一 `font-variant-numeric: tabular-nums`，字号层级拉开（KPI 数字 28–32px，正文 14px，辅助 12px）。
- 标题层级收紧：卡片标题 `text-sm font-medium` 配 `text-muted-foreground` 的描述行，不再每个卡片都是大标题。

### 质感细节

- 卡片：`rounded-xl` + 极浅投影（`shadow-sm`），hover 不浮起（Operate 模式不做花哨浮起，保持稳重）。
- 运行中队列卡片左侧 3px 琥珀色边条作为状态锚点。
- 队列轮询活跃时，KPI「待处理条目」数字变化加短暂 transition（`transition-colors`/数字滚动可选，第一版只做颜色淡入）。

## 5. 状态与反馈设计

| 场景 | 现状 | 方案 |
| --- | --- | --- |
| 首次加载 | 空白卡片 | 各区块 Skeleton（shadcn `skeleton.tsx` 已有） |
| 无商品/无队列/无数据 | 空列表 | 空态组件（`empty.tsx` 已有）：图标 + 一句话 + 主操作按钮（如「新建商品」） |
| 服务不可用 | 仅 header 红徽章 | 页面顶部再加一条 Alert 横幅，说明影响与操作（重试） |
| 队列运行中 | 文字 status | 进度条 + 当前条目名 + 呼吸点动画 |
| 入队/追加成功 | toast | 保持 toast，同时队列区乐观刷新 |
| 删除确认 | 已有 AlertDialog | 保持，统一文案格式：动作 + 影响范围（沿用「使用该标签的商品」提示） |

## 6. 逐区块改造要点

1. **Header**：标题 + 服务状态徽章 + 深色模式开关；sticky 保持。
2. **KpiStrip（新）**：5 指标卡，从现有 props 派生，无新 API。
3. **QueuesCard → QueueMonitor**：拆成「运行中（大）+ 其余（列表）」；新建队列表单收进 Dialog 或折叠面板，不常驻占位。
4. **ProductsCard**：表格化（当前是列表样式），统计列右对齐 tabular-nums；勾选入队保持。
5. **TagsCard**：压缩为紧凑列表（名称 + 启用开关 + 商品数），编辑/新建收进 Dialog。
6. **ItemsCard**：全宽表格 + 骨架屏 + 空态。
7. **AiCard**：供应商管理与工具调用审计合并为 Tabs 卡片，置底。

## 7. 实施步骤（分阶段，每阶段可独立验收）

- **P1 结构重排**：App.tsx 改网格布局 + KPI 概览条 + AI Tabs 收纳；纯 JSX 结构调整，不改状态逻辑、不改 API。预计改动集中在 `App.tsx` 和各 section 的外层容器。
- **P2 视觉系统**：index.css 暖色 token + 琥珀 accent + 深色模式开关；进度条/状态色规范落到 QueuesCard。
- **P3 状态与反馈**：Skeleton、空态、Alert 横幅、运行态动画。
- **P4 精修**：移动端适配走查、删除确认文案统一、数字滚动等细节。

每阶段完成后：`cargo test export_bindings`（若动了 dto，本期预计不动）→ `npm run build` → 手动走查。

## 8. 边界与反目标

- **不改**：后端 API、App.tsx 的数据加载/轮询/入队逻辑（只移动位置不改行为）、shadcn 组件库本身、ts-rs 类型同步机制。
- **反目标**：不引入路由/状态管理库；不做营销化的视觉炫技（大渐变、3D、视差）；不为「好看」牺牲信息密度——这是工具不是展示页；不新增后端接口。

## 9. 假设（待确认）

1. 用户只有你一人，桌面优先，移动端能用即可。
2. 「队列状态」是你打开页面最想看的第一信息——如果其实是商品统计或原始数据，主区英雄位需调整。
3. 琥珀黄品牌方向可接受；若偏好冷静工具风（蓝灰系），视觉方案可整体替换，布局方案不受影响。

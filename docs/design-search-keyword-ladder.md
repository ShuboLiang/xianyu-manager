# 搜索关键词梯队：规则生成 + 自适应降级

## 背景与问题

AI 驱动抓取（`GATEWAY=webbridge`）中，默认搜索词 = 商品名原文
（`crawl_agent_service.rs` 把 `product.name` 作为 `xianyu_search` 的
`default_keyword`）。卖家标题写法五花八门：商品叫「i3 8100」，很多卖家只写
「8100」，窄搜直接漏掉这部分在售商品。

现状下「搜什么词、搜几次」全凭 AI 临场决定（提示词只说「候选质量差时可修正
关键词再搜一次」），行为不确定、不可复现。

## 目标

- 商品名→搜索关键词的扩展行为**确定、可复现**，不依赖 AI 临场发挥；
- 宽词兜底找回漏抓商品，但**不把候选池灌满噪声**；
- AI 的角色不变（筛选 + 提交），token 消耗基本不涨；
- 本期不动数据库、不动前端（手动别名是后续扩展，见「非目标」）。

## 总体设计

`xianyu_search` 工具不再只搜一次。AI 调一次工具，工具内部按「关键词梯队」
从窄到宽自适应搜索、合并去重，把最终候选池一次返回给 AI。

```
gen_keywords(商品名) → 关键词梯队（从窄到宽）
  ↓
搜梯队[0]（原词）        → 候选 ≥ ENOUGH_THRESHOLD？够则停
  不够 → 追加搜梯队[1]   → 按 URL 去重合并 → 再判断
  不够 → 追加搜梯队[2]（需过宽词准入门槛）
  ↓
合并后的候选池返回给 AI → AI 筛选 ≤8 个 → save_crawl_result（不变）
```

### 关键词梯队生成：`gen_keywords(name) -> Vec<String>`

纯函数，放在 `application/ai/` 下（新文件 `keyword_ladder.rs`），便于单测。

1. **归一化**：trim、全角转半角、压缩连续空格、大小写不敏感处理。
2. **分词**：不上中文分词库，按字符类型切 run（ASCII 字母 / 数字 / 中日韩
   字符 / 空格·连字符），类型变化即断开：`i3 8100` → `[i3, 8100]`，
   `RTX4090` → `[rtx, 4090]`，`小米手环8` → `[小米手环, 8]`。
   中文 run 内部不切，品牌靠词典**前缀匹配**剥离（`小米手环` 剥掉 `小米`），
   剥完剩下的宽词仍要过下方的准入门槛。
3. **生成变体**（产出顺序即梯队顺序）：
   - 原词本身（梯队首位，永远是它）；
   - 分隔符变体：空格↔连字符（`i3 8100` → `i3-8100`）、黏连拆分
     （`小米手环8` → `小米手环 8`）；
   - 去品牌变体：删除命中品牌词典的 token（`i3 8100` → `8100`）。
     品牌词典是代码里的小常量表（intel/amd/nvidia/小米/华为/苹果等几十个），
     后续发现漏了直接补。
4. **过滤与安全阀**：
   - 与原词重复的变体丢弃；
   - 过短变体丢弃（整体 < 3 字符，或纯数字 < 4 位）；
   - **宽词准入门槛**：去品牌后的宽词若区分度不足（如「手环8」这类
     「通用词 + 个位数字」）则不进梯队——宁可候选少，不灌噪声。
     判定规则：宽词必须是「纯型号形态」（如 `8100`、`rtx 4090`）或仍含
     有区分度的 token；`8100` 放行（搜出来基本都是该型号 CPU），
     `手环8` 不放行；
   - 梯队总长封顶 `MAX_KEYWORDS = 4`。

示例：

| 商品名     | 梯队                                |
| ---------- | ----------------------------------- |
| i3 8100    | `i3 8100`, `i3-8100`, `8100`        |
| 小米手环8  | `小米手环8`, `小米手环 8`           |
| RTX 4090   | `RTX 4090`, `RTX-4090`, `4090`      |

注：`小米手环8` 剥掉品牌后的宽词是 `手环8`（「通用词 + 个位数字」，
区分度不足），被准入门槛丢弃，故不进梯队；`8100`、`4090` 是纯型号形态，
放行。

### 自适应降级搜索

在 `XianyuSearchTool::execute` 内实现：

- 从梯队首位开始搜索，每轮结果**按 URL 去重**合并进候选池；
- 合并后候选数 ≥ `ENOUGH_THRESHOLD`（初值 15）即停止；
- 梯队耗尽或候选池达到上限（`MAX_CANDIDATES`，初值 60，防 token 膨胀）
  也停止；
- 大部分商品第一轮窄搜即停——WebBridge 调用不增加；只有真漏抓的商品
  才会多搜 1~2 轮。

### AI 侧的变化

- `xianyu_search` 的 description 更新为「内部自动按关键词梯队降级搜索」；
  AI 仍可手动传 `keyword` 作为补救手段（此时直接搜该词，不走梯队）；
- 系统提示词第 1 条相应改写，去掉「自行修正关键词」的模糊表述；
- 返回值结构增加 `searched_keywords` 字段（实际搜过的词），便于排查
  与审计（`ai_tool_calls` 参数/结果里都能看到）。

### 常量

集中在 `keyword_ladder.rs`，不顺手再调：

| 常量              | 初值 | 说明                     |
| ----------------- | ---- | ------------------------ |
| `MAX_KEYWORDS`    | 4    | 梯队长度上限             |
| `ENOUGH_THRESHOLD`| 15   | 候选够了就停的阈值       |
| `MAX_CANDIDATES`  | 60   | 合并候选池上限           |

## 改动范围

- 新增 `src/application/ai/keyword_ladder.rs`：`gen_keywords` 纯函数 + 品牌
  词典 + 常量 + 单元测试；
- 修改 `src/application/ai/crawl_agent_service.rs`：
  `XianyuSearchTool` 改为持有梯队并做降级搜索、description/返回值更新、
  系统提示词改写；
- 不动：数据库、dto、前端、WebBridge 客户端。

## 测试

- `gen_keywords` 单测：归一化、分词、变体生成、宽词门槛、封顶；
- 降级逻辑单测：用 mock gateway 验证「够了就停」「不够才追加」「去重」。

## 非目标（后续扩展）

- **商品级手动别名**（数据库加字段，覆盖/追加规则生成的梯队）：等跑一段
  时间发现规则覆盖不了的商品（俗称类，如「十三香」）再做；
- AI 批量预生成别名；
- 品牌词典做成可配置（目前写死即可）。
